# P0902 Statement Level Trigger with Auditing and Exception Handling

## Statement Trigger - TRG_ACCOUNTS_AUDIT

You are working as a database developer for a small online banking system. The bank maintains a table named ACCOUNTS that stores each customer's account balance. Your task is to create a statement-level trigger that records every DML operation performed on this table.

The statement-level trigger TRG_ACCOUNTS_AUDIT fires once for each INSERT, UPDATE, or DELETE statement run on the ACCOUNTS table. It does not fire once per row. Instead, it captures information about the DML operation, such as the date and who performed the action. If any part of the trigger fails, the trigger should display an error message.

## Step 1: Drop Tables

Drop the ACCOUNTS, ACCOUNTS_AUDIT, and ACCOUNT_ERROR_LOG tables if they exist.

## Step 2: Create Tables

### ACCOUNTS Table

Stores data about bank customers and their account balances.
```sql
CREATE TABLE accounts (
    account_id   INTEGER        NOT NULL,
    first_name   VARCHAR2(30)   NOT NULL,
    last_name    VARCHAR2(30)   NOT NULL,
    balance      NUMBER(12,2)   NOT NULL,
    CONSTRAINT accounts_pk
        PRIMARY KEY (account_id) );
```

### ACCOUNTS_AUDIT Table

Records each DML statement (INSERT, UPDATE, DELETE) that affects the ACCOUNTS table. Each entry represents a single SQL statement that modified data, not individual rows.
```sql
CREATE TABLE accounts_audit (
    audit_id     INTEGER
        GENERATED ALWAYS AS IDENTITY
        NOCACHE,
    trigger_name VARCHAR(30),
    action_type  VARCHAR2(10)   NOT NULL,
    action_date  DATE           NOT NULL,
    user_id      VARCHAR2(30)   NOT NULL,
    CONSTRAINT accounts_audit_pk
        PRIMARY KEY (audit_id) );
```

### ACCOUNT_ERROR_LOG Table

Records any errors that occur during a DML operation against the ACCOUNTS table.
```sql
CREATE TABLE account_error_log (
    error_id      INTEGER
        GENERATED ALWAYS AS IDENTITY
        NOCACHE,
    error_date    DATE           NOT NULL,
    user_id       VARCHAR2(20)   NOT NULL,
    error_code    VARCHAR2(20)   NOT NULL,
    error_message VARCHAR2(4000) NOT NULL,
    CONSTRAINT account_error_log_pk
        PRIMARY KEY (error_id) );
```

## Step 3: Create the Statement-Level Trigger - TRG_ACCOUNTS_AUDIT

- Fires AFTER INSERT OR UPDATE OR DELETE on ACCOUNTS.
- Determines the DML action fired by the trigger.
- Insert one row into ACCOUNTS_AUDIT table.
- Displays a message of completion.
- If a trigger operation fails, it provides an exception routine that displays a message with the SQL error code and error message.

# P0903 Row Trigger

## Step 1: Create Function

Create a function called **convert_numeric_grade** (same as chapter 7) that converts a numeric grade to a letter grade. Use the same values as before. Use a CASE structure. IN parameter is the numeric grade and RETURN a VARCHAR2 (letter grade).

## Step 2: Create Log Table

Create a LOG table called **GL_ENROLL_UPDATE_LOG** to capture the audit trail of changes to the gl_enrollments_copy table. The table will contain the following columns:

| Column | Type | Default |
|---|---|---|
| user_id | VARCHAR2(30) | DEFAULT USER |
| last_change_date | DATE | DEFAULT SYSDATE |
| section_id | NUMBER(5, 0) | |
| student_no | NUMBER(7, 0) | |
| old_grade | VARCHAR2(2) | |
| new_grade | VARCHAR2(2) | |
| log_action | VARCHAR2(30) | |

## Step 3: Create trigger

Create an AFTER UPDATE row trigger called **GL_ENROLL_UPDATE_TRG** on the gl_enrollments_copy table that fires after a change is made to the letter grade. The trigger inserts a row into the GL_ENROLL_UPDATE_LOG table. Use a nested IF statement or CASE structure to determine the ACTION to insert. When the old letter grade is the same as the new letter grade, insert 'grade is the same'. When the old letter grade is less than the new letter grade, insert 'grade went up'. When the old letter grade is greater than the new letter grade, insert 'grade went down'.
